* Local Ollama Models - Tool Support Status

*IMPORTANT*: As of OpenCode 1.3.3, local Ollama models do NOT work reliably
with tool calling, even when the model supports tools natively.

** Root Cause

The =@ai-sdk/openai-compatible= provider used by OpenCode does not properly
pass tools to local Ollama models. Even though:

1. Ollama reports =tools= capability for models like devstral
2. Direct API calls with tools work correctly (tested with curl)
3. The model config has =tools: true=

OpenCode still doesn't send tools to the model, so the model cannot perform
file operations.

** Proof: Devstral Works Natively

Direct API call with tools works:
#+begin_src shell
curl -s http://127.0.0.1:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "devstral:24b",
    "messages": [{"role": "user", "content": "Read the file /tmp/test.txt"}],
    "tools": [{
      "type": "function",
      "function": {
        "name": "read_file",
        "description": "Read a file from the filesystem",
        "parameters": {
          "type": "object",
          "properties": {
            "path": {"type": "string", "description": "The file path to read"}
          },
          "required": ["path"]
        }
      }
    }]
  }'
#+end_src

Returns proper tool call:
#+begin_src json
{
  "role": "assistant",
  "content": "",
  "tool_calls": [{
    "id": "call_xxx",
    "type": "function",
    "function": {
      "name": "read_file",
      "arguments": "{\"path\":\"/tmp/test.txt\"}"
    }
  }]
}
#+end_src

But OpenCode doesn't pass tools to the model.

* Goose - Working Local Alternative

[[https://github.com/block/goose][Goose]] is Block's open-source AI agent that has *native Ollama support with working tool calling*.

** Installation

#+begin_src shell
# Install Goose
curl -fsSL https://github.com/block/goose/releases/latest/download/download_cli.sh | CONFIGURE=false bash
#+end_src

** Configuration

Goose config at =~/.config/goose/config.yaml=:
#+begin_src yaml
GOOSE_PROVIDER: ollama
OLLAMA_HOST: http://localhost:11434
GOOSE_MODEL: devstral:24b
#+end_src

** Verified Working (May 2026)

| Model        | Tool Support | Status  | Notes                            |
|--------------+--------------+---------+----------------------------------|
| devstral:24b | Yes          | WORKING | Full tool calling support        |

** Usage

#+begin_src shell
# Interactive session
goose session

# One-shot command
goose run --text "List files in this directory"

# From Emacs via agent-shell
M-x agent-shell-goose-start-agent
# or C-x a g
#+end_src

** Why Goose Works When OpenCode Doesn't

Goose uses its own =ollama= provider that properly passes tools to local models.
OpenCode uses =@ai-sdk/openai-compatible= which doesn't handle local model tools correctly.

** Configuration

The =opencode.json= file configures:
- Default model: =ollama/devstral:24b= (but tools don't work)
- Provider: Ollama via OpenAI-compatible API at =http://127.0.0.1:11434/v1=
- Plugin: opencode-power-pack for additional skills
